Create connection status endpoint for the UI to check OpenCode connectivity.

**GET**: Return connection status
```typescript
{
  mode: 'auto' | 'custom',
  baseUrl: string | null,
  connected: boolean,
  healthy: boolean,
  version: string | null,
  lastConnected: string | null
}
```

**PUT**: Update connection mode
- Request body: `{ mode: 'auto' | 'custom', baseUrl?: string }`
- Validates: custom mode requires baseUrl
- Stores in opencode_connection table (singleton, id=1)

Implementation:
1. Get current config from opencode_connection table (or default to auto mode)
2. Call checkOpencodeHealth() from opencode.service.ts to verify connectivity
3. Return combined status

Use existing opencode.service.ts patterns for health checks.
If connection table is empty, create default row with mode='auto'.

Create endpoint for per-prompt function settings overrides.

**Route params**:
- `[id]`: prompt ID (integer)
- `[type]`: function type (executor, judge, improve, council)

**GET**: Return prompt-specific override or null
- Response: `{ data: PromptFunctionSetting | null }`

**PUT**: Create or update prompt-specific override
- Request body: `{ modelOverride?, temperature?, maxTokens?, promptLinkId? }`
- All fields optional (null = use global default)
- Validates: if modelOverride provided, must be valid model ID format

**DELETE**: Remove prompt-specific override
- Returns to using global defaults

Implementation:
1. Parse route params (id, type)
2. Validate prompt exists
3. Upsert into prompt_function_settings table
4. Return updated/created record

Follow existing API patterns with authenticateRequest, validation, error handling.
