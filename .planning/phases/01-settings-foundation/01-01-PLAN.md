  <name>Task 1: Add settings tables to database schema</name>
  <files>src/lib/server/db/schema.ts</files>
  <action>
Add four new tables to schema.ts following existing Drizzle ORM patterns:

1. **opencode_connection** (singleton - id always 1):
   - id INTEGER PRIMARY KEY CHECK (id = 1)
   - mode TEXT DEFAULT 'auto' ('auto' or 'custom')
   - base_url TEXT (nullable, for custom mode)
   - last_connected TEXT (timestamp)
   - created_at, updated_at timestamps

2. **function_defaults** (4 rows max, one per function type):
   - id INTEGER PRIMARY KEY
   - function_type TEXT NOT NULL UNIQUE ('executor', 'judge', 'improve', 'council')
   - model_id TEXT NOT NULL (format: 'providerID/modelID')
   - temperature REAL DEFAULT based on function type (executor: 0.7, judge: 0.3, improve: 0.7, council: 0.5)
   - max_tokens INTEGER DEFAULT based on function type (executor: 4096, judge: 2048, improve: 4096, council: 8192)
   - prompt_id INTEGER REFERENCES prompts(id) (nullable, for prompt linking)
   - created_at, updated_at timestamps

3. **prompt_function_settings** (per-prompt overrides):
   - id INTEGER PRIMARY KEY
   - prompt_id INTEGER NOT NULL REFERENCES prompts(id)
   - function_type TEXT NOT NULL
   - model_override TEXT (nullable)
   - temperature REAL (nullable)
   - max_tokens INTEGER (nullable)
   - prompt_link_id INTEGER REFERENCES prompts(id) (nullable)
   - UNIQUE(prompt_id, function_type)

4. **council_agents** (council repeater pattern):
   - id INTEGER PRIMARY KEY
   - parent_type TEXT NOT NULL ('function_defaults' or 'prompt_function_settings')
   - parent_id INTEGER NOT NULL
   - agent_order INTEGER NOT NULL
   - model_id TEXT NOT NULL
   - temperature REAL DEFAULT 0.5
   - max_tokens INTEGER DEFAULT 8192
   - prompt_link_id INTEGER REFERENCES prompts(id) (nullable)

Also export types using $inferSelect and $inferInsert patterns.
Do NOT use Prisma-style syntax - use Drizzle sqliteTable patterns matching existing schema.

<task type="auto">
  <name>Task 3: Create settings-cascade.service.ts</name>
  <files>src/lib/server/services/settings-cascade.service.ts</files>
  <action>
Create cascade resolution service implementing 3-level precedence: Run > Prompt > Global Default.

1. **Resolution types**:
```typescript
export type CascadeLevel = 'run' | 'prompt' | 'default';

export interface ResolvedSetting<T> {
  value: T;
  source: CascadeLevel;
}

export interface ResolutionResult {
  modelId: ResolvedSetting<string>;
  temperature: ResolvedSetting<number>;
  maxTokens: ResolvedSetting<number>;
  promptId?: number | null;
}
```

2. **Main resolution function**:
```typescript
export async function resolveFunctionSettings(options: {
  functionType: FunctionType;
  promptId?: number;
  runOverrides?: {
    modelId?: string;
    temperature?: number;
    maxTokens?: number;
  };
}): Promise<ResolutionResult>
```

3. **Resolution logic** (for each setting: modelId, temperature, maxTokens):
   - If runOverrides provides value → use it, source = 'run'
   - Else if promptId exists and prompt_function_settings has override → use it, source = 'prompt'
   - Else use function_defaults → source = 'default'

4. **Helper function**:
   - `getPromptFunctionSettings(promptId: number, functionType: FunctionType): Promise<PromptFunctionSetting | null>`

Import function-defaults.service for global defaults.
The cascade must ALWAYS return a value (global defaults are guaranteed).
  </action>
  <verify>npm run check passes; service exports resolveFunctionSettings with proper typing</verify>
  <done>Cascade resolution returns effective settings with model_source tracking for all 3 levels</done>
